Quadra 0.43.1 fixes VR on Roblox 0.746 and lets the launcher start on distributions without GLibUnix. Nothing else changes from 0.43.0.

- **VR on Roblox 0.746:** VR said "Unavailable: unsupported client graphics device or VR emulator". Roblox 0.746 added two methods to its graphics device, which moved the methods that report and switch the VR device (getVR and setVR) two slots down, and Quadra looked for them at the old slots. VR was not removed from the client: the VR device and its methods are unchanged. Quadra now finds getVR and setVR by their code, so VR works on 0.745 and 0.746.
- **Launcher signals:** the launcher handles SIGTERM, SIGINT and SIGHUP through `GLib.unix_signal_add` again instead of `GLibUnix`, which some distributions' GLib bindings do not provide.
- Everything in the 0.43.0 notes still applies: the shared launcher state, Discord Rich Presence for Flatpak and Snap clients, the GNOME 51 Flatpak and the Nix Rosemary variant.

Validation: VR was run in a live game on Roblox 0.746.0.7461264 with Rosemary on a Quest 2 over WiVRn: the VR device attached, the session reached focused and frames held 90 fps at 90 Hz. The VR setup was also checked offline against the 0.745.0.7451137 and 0.746.0.7461264 clients, finding getVR and setVR at slots 17/18 and 19/20. The 470 unit tests and the native tests pass. The Darling VR build was only build-checked, not run in a game. The GLibUnix change was not tested on a distribution without GLibUnix.

Fully close and reopen Quadra after updating. Studio is not in the Flatpak. OpenGL remains the default for the game on Darling; VR requires OpenGL or Vulkan/Zink. Native packages include the matching Metal host and framework. Install `.pkg.tar.zst` on Arch derivatives, `.deb` on Ubuntu 24.04+/Debian 13+, the binary `.rpm` on current Fedora, or the Flatpak with `flatpak install --user quadrahq-0.43.1-x86_64.flatpak` (it uses Flathub's GNOME 51 runtime). Darling/CiderDarling downloads remain separate. Source archives, build recipes and `SHA256SUMS` are attached.

Quadra 0.42 makes Rosemary the default runtime for new installs, asks before VR is turned on, adds controllers for Darling and a memory guard for Quadra M2VK on integrated AMD graphics, and sorts the source tree by runtime.

- **Rosemary is the default:** a new install runs Roblox with Rosemary, and Darling is marked outdated. `install.sh` asks which to use (`--backend rosemary` or `--backend darling`). Rosemary needs no Darling and nothing to build: Quadra downloads Rosemary and Roblox the first time you press Play. An install that already exists keeps its runtime, and the Flatpak and Nix packages, which carry Darling, stay on Darling. Switch later with Settings → Rosemary → "Run Roblox with". `--uninstall --purge` now also removes Rosemary's files.
- **VR asks first:** VR works by changing the running client's memory, which is also what a Roblox cheat does, so Roblox's anti-cheat could flag it. The chance is thought to be low, but it is not known. A dialog says so before VR is turned on, with a "Don't show this again" switch that is kept only if you go ahead. Installs that already have VR on are not asked.
- **Controllers (Darling):** Linux gamepads (Xbox, DualSense, Switch Pro, and Steam Input's virtual pad) appear to Roblox as `GCController`s. No rumble, motion, lights or battery yet; `QUADRA_GAMEPAD=0` turns it off.
- **Quadra M2VK on integrated AMD graphics:** the host now reads the GPU's GTT counters and refuses a large host-visible buffer that would use it up, which is what lost the Vulkan device in #38. A lost device closes the game with a memory report instead of a segmentation fault. Other GPUs are not checked.
- **Also:** `QUADRA_REFRESH_RATE=<hz>` for testing high-refresh displays, `MACOBLOX_METAL_PRESENT_MODE=fifo_relaxed`, `tools/check_imports.py`, and AMD memory totals in the hardware report.
- **Source tree:** Darling's native code is in `darling/`, Rosemary's VR build in `rosemary/vr/`, the VR device both use in `vr/`, and the launcher's runtime-specific modules in `quadra/darling/` and `quadra/rosemary/`. `CONTRIBUTING.md` is new. Nothing changes for players, except that the first launch after updating rebuilds the shim.

Validation: 452 unit and native tests and 90 launcher tests pass, and the nine GTK fixtures pass headless. The shim, Wayland helper and stub frameworks built from the new layout match the old build apart from the linker's UUID, and the Rosemary VR library builds. The shim, the Metal framework and the Rust host also build from the project's generated source archive, and the package payload installer stages a working launcher from it. The controller code was tested against a virtual pad on `/dev/uinput` in real Darling and natively. The GTT guard was tested against fake sysfs and through the C ABI on an RTX 3060 Ti, which skips it. Not run: controllers with a real pad or in the Roblox client, the GTT guard on an affected AMD laptop, a Rosemary-only install through `install.sh` on a clean machine, and the Flatpak and Nix packages with the new layout. CI builds the Arch, Ubuntu and Fedora packages.

Fully close and reopen Quadra after updating. Studio is not in the Flatpak. OpenGL remains the default for the game on Darling; VR requires OpenGL or Vulkan/Zink. Native packages include the matching Metal host and framework. Install `.pkg.tar.zst` on Arch derivatives, `.deb` on Ubuntu 24.04+/Debian 13+, or the binary `.rpm` on current Fedora. Darling/CiderDarling downloads remain separate. Source archives, build recipes and `SHA256SUMS` are attached.

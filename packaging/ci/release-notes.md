Quadra 0.41 brings back the old launcher layout and makes Rosemary a runtime Quadra installs and runs for you, with VR.

- **Old layout back:** 0.40's grouped sidebar and Home page are gone. The sidebar lists Play, Settings, Studio, Servers, Mods and Info again, the Play page is the old dashboard (its badge says "Darling" or "Rosemary" for the runtime in use), and Settings is one Environment page with the tab bar plus a Rosemary tab. The new settings (tray icon, location notification, region, telemetry, CPU limit) sit in those pages. The direct start with its splash, the tray icon and the Servers page stay.
- **Rosemary (experimental, Settings → Rosemary):** Quadra installs Rosemary (from its release, checksum checked) and Roblox for it when you press Play or pick it, with no other tool needed. This also fixes "Install Roblox" doing nothing when Rosemary was selected. Mods apply into Rosemary's own client with backups per build, the CPU core limit is set before it starts, the Discord status works, and its options (presentation mode, refresh rate, title bar, menu placement, pointer and Command-key settings) have rows. "Hide the macOS menu bar" also hides Rosemary's menu. You can go back to the previous Roblox build, an update-required exit installs the new build and starts again, and Sign out clears Rosemary's cookies.
- **Settings only one runtime reads** (the DNS server, telemetry blocking, the renderer, Quadra M2VK, the input tweaks, CiderDarling) are greyed out and tagged "Darling only" while Rosemary is chosen.
- **VR on Rosemary:** needs Quadra's build of Rosemary (QuadraHQ/rosemary-fork, branch quadra-vr; set its path under Settings → Rosemary, or run with `QUADRA_ROSEMARY=<path>`), which Quadra does not install yet. The VR library is built on first use and needs clang and Darling's runtime files. An option runs Roblox's OpenGL on Vulkan through Mesa's zink. Tried on a Quest 2 over WiVRn by the owner (it works); controller input, haptics and long sessions were not checked in detail.
- **Fast flags:** your flags are kept in Quadra's own config, apart from the workaround flags Darling adds (RakNet transport, HTTP throttling), which only go into Darling's client. Before, the Rosemary client received those too. Existing setups carry over.
- **Known:** networking felt slow in one VR session on Rosemary. The log shows the game already uses RakNet and Rosemary's sockets and timers measure the same as native Linux; the cause is not found.
- Everything in the 0.40 and 0.40.p1 notes still applies.

Validation: 82 launcher unit tests pass, with a fake Rosemary for the session paths. Against the real Rosemary 0.5.0 and Roblox 0.745 on a virtual display: the CPU limit, environment, flags and mods. An end-to-end VR test against a headless OpenXR emulator passes six checks (client patched, VR device attached, session focused, frame loop paced, head pose read). The install-then-start path was run with the install and the game stubbed; the real Darling install and a real Rosemary first-time install were not run in the launcher.

Fully close and reopen Quadra after updating. Studio is not in the Flatpak. OpenGL remains the default for the game; VR requires OpenGL or Vulkan/Zink. Native packages include the matching Metal host and framework. Install `.pkg.tar.zst` on Arch derivatives, `.deb` on Ubuntu 24.04+/Debian 13+, or the binary `.rpm` on current Fedora. Darling/CiderDarling downloads remain separate. Source archives, build recipes and `SHA256SUMS` are attached.
